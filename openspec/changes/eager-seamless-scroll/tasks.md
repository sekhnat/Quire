## 7. Defect repairs found by the 6.2 emulator smoke

- [x] 7.1 Fix the frame-eval result encoding in `ContinuousBookWebView`: the wrapper stringified every frame answer (`String(r)`), so object answers decoded as `"[object Object]"`, and the bridge's answer is JSON-*quoted*, which `offsetTopForId`/`offsetTopForDecoration`/`captureAnchor` parsed without unwrapping — each fragment, decoration and anchor lookup therefore returned `null` and fell back to resource-start progression or the progression anchor. Object answers are now JSON-encoded, and a single `frameResultJson`/`frameResultTop` unwraps the quoted answer. Verified on the emulator with the real reader: `A deep target A` (the fixture's fragment near the end of a 8,418px chapter) is scrolled into view, the shallow and deep fragments of that same resource each land on their own authored target (`a toc fragment deep inside a resource is scrolled into view`), and an exact search match is both underlined and positioned visibly (`opening a snippet target in continuous scroll mode underlines the exact passage`, whose new assertion measures the underline's place in the reader viewport).
- [x] 7.2 Report outer-surface scrolling to the navigator again: `ContinuousBookWebView.onScrollChanged` only mirrored a stale `scrollYSync` (it was the FrameLayout's own scroll callback, which never fires) and no scroll listener was bound on the shell WebView, so `onProgressionChanged` never fired for user scrolling and `currentLocator` (progress, saved position, current-chapter TOC, time-left estimate) stayed frozen at the readiness position. The shell WebView now binds `setOnScrollChangeListener`, mirrors its CSS-px position and publishes the locator at most every 120ms while scrolling. Verified with a real injected drag: `scrolling across a chapter seam reports the visible resource and progression` asserts the reported locator crosses into the next original href with its own progression, that the reported resource is the one on screen (its heading above the viewport, the next chapter's below it), and that the position persisted on close is no longer the book start.
- [x] 7.3 Extend the deterministic fixture with a fragment deep inside a long chapter (`#target-deep` plus a TOC entry) and add the real-reader regression coverage for 7.1 and 7.2 — fragment landing, same-resource distinct fragments, viewport-relative underline placement, seam-crossing progress and saved position. The temporary diagnostics used during diagnosis were removed; `ReaderContinuousScrollTest` (7 tests) and `ReaderTargetTest` (9 tests) pass together in the isolated `.dbtest` app.
- [x] 7.4 Resolve viewport-relative publisher lengths against the reader viewport instead of the frame's expanded box.
